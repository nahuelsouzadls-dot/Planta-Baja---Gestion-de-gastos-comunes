# Tarea: E2 — Roles de base separados (dueño y app)

## Contexto
`docs/arquitectura/almacenamiento.md` §2: **los triggers append-only solo protegen si la app no es dueña de las tablas.** El dueño puede `ALTER TABLE … DISABLE TRIGGER` y un superusuario puede `SET session_replication_role = replica`. Hoy todo corre como `postgres` (superusuario).

## Decisiones
- `gc_owner`: dueño del esquema; lo usan **solo** las migraciones (y la creación de la base de tests).
- `gc_app`: el que usa Django al correr (`web`, `worker`, `beat`): `CONNECT`, `USAGE` en el esquema, `SELECT, INSERT, UPDATE, DELETE` en las tablas y `USAGE, SELECT` en las secuencias; **sin** `TRUNCATE`, sin `ALTER`, sin ser dueño ni superusuario. `ALTER DEFAULT PRIVILEGES FOR ROLE gc_owner` para que las tablas nuevas de futuras migraciones queden con los mismos permisos.
- En Docker: un script en `docker/postgres/init/` que crea los dos roles en la primera inicialización del volumen (con contraseñas desde `backend/.env`, nunca en el repo).
- Django: `DATABASES['default']` con `gc_app`; las migraciones se corren con `DB_USER=gc_owner` (el `Makefile`, la CI y el comando de release de Railway lo hacen así).
- **Tests:** pytest necesita crear la base de tests, así que corre con `gc_owner`. Para que los tests de seguridad prueben lo real, agregá tests que abran una conexión **como `gc_app`** y verifiquen que no puede deshabilitar triggers, ni hacer `TRUNCATE`, ni `ALTER TABLE`, ni `SET session_replication_role`.
- Actualizá `Makefile`, `docs/docker.md`, `docs/ci.md` y la CI.

## Cuidado
Cambia cómo se corren los tests: si `web` pasa a `gc_app`, `docker compose run --rm web pytest` deja de poder crear la base de tests. El `Makefile` y la documentación tienen que dejar un único comando correcto (`make test`).

## Tests
- Como `gc_app`: `ALTER TABLE ledger_ledgerentry DISABLE TRIGGER ALL`, `TRUNCATE`, `SET session_replication_role = replica` y `UPDATE ledger_ledgerentry` fallan; un `INSERT` normal de un asiento por el servicio funciona.
- La app completa funciona como `gc_app` (seed de la demo y un par de endpoints).
